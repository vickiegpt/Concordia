# Kimi K2.6 Numerical Correctness Proof

This record captures the strict NVIDIA passthrough path after fixing real
cuBLAS forwarding and exposing Kimi CUDA fatbin/CUBIN payloads to the Rust SASS
lifter.

The proof has two contracts:

1. Numerical equivalence: native CUDA Kimi output must match the hooked
   `LD_PRELOAD` output byte-for-byte under deterministic sampling.
2. Translation coverage: synthetic PTX->SASS->PTX round-trip tests must pass,
   and the real Kimi runner must expose fatbin/CUBIN modules to the SASS lifter.

## Shim Fix Under Test

For `--features nvidia,embed_cudart`, `zluda/build.rs` defines
`HETGPU_SHIM_ENABLE_REAL_CUBLAS_BY_DEFAULT` when SIFIVE is not enabled. That makes
the cuBLAS shim default to forwarding real NVIDIA cuBLAS calls in the passthrough
path.

`zluda/src/cublas_shim.c` now:

- gates real forwarding with `HETGPU_CUBLAS_FORWARD_REAL`
- supports `HETGPU_REAL_CUBLAS_PATH` before trying `libcublas.so.12` and
  `libcublas.so`
- forwards handle, stream, pointer-mode, atomics-mode, math-mode, and SGEMM
  calls when real cuBLAS is available
- maps cudart-shim managed stream objects to `NULL` before forwarding them to
  real cuBLAS
- keeps the lazy SIFIVE submit/staging path available for virtual/SIFIVE builds

The old failure was:

```text
CUDA error: CUBLAS_STATUS_NOT_SUPPORTED
current device: 0, in function ggml_cuda_op_mul_mat_cublas
cublasSgemm_v2(...)
```

`HETGPU_SIFIVE_ALLOW_HOST_GEMM_FALLBACK=1` is not a valid proof escape for the real
NVIDIA path, because real GPU device pointers cannot be treated as host memory.

## Kimi SASS/CUBIN Exposure

The cudart shim now accepts `HETGPU_CUDART_PREFER_FATBIN_CUBIN_FOR_SASS=1`.
When set, `__cudaRegisterFatBinary` keeps the whole CUDA fatbin available for
launch-time module load instead of selecting only embedded PTX.

The NVIDIA module loader now:

- scans CUDA fatbin entries for ELF/CUBIN payloads
- supports raw ELF/CUBIN entries
- supports zstd and LZ4-compressed ELF/CUBIN entries
- handles Kimi's real fatbin layout where ELF entries have `payload_size=0` and
  the real CUBIN span is in `padded_payload_size`
- logs the fatbin entry shape under `HETGPU_SASS_LIFTER_LOG=1`

Regression tests cover both compressed and zero-payload-size fatbin CUBIN
entries.

## Current Proof Boundary

Proven now:

- The Rust fuzzer passes for the configured deterministic seed.
- The shell regression harness passes, including fake real-cuBLAS forwarding and
  cudart fatbin preference probes.
- The real LD_PRELOAD synthetic round-trip suite passes 11/11 SM120 cases.
- Kimi K2.6 strict cudart e2e exposes 14 fatbin/CUBIN modules to the Rust SASS
  lifter and writes a lifted PTX dump.
- Kimi K2.6 native CUDA vs strict cudart-shim
  `LD_PRELOAD=target/debug/libhetgpu_cuda_shim.so:target/debug/libnvcuda.so`
  produces byte-for-byte identical generated stdout with 1/62 GPU layers
  offloaded and 14 SASS lifter markers.

Still outside this proof:

- This is a finite deterministic Kimi prompt/offload proof, not a universal proof
  over every prompt, generation length, or model quantization.
- The lifted PTX contains diagnostics for unsupported SASS opcodes; the proof
  establishes capture, lifter execution, and deterministic Kimi output
  preservation for this run, not complete semantic coverage of every SM120
  opcode.
